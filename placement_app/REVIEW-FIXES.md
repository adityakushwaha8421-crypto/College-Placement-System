# PlacementOS project review — 31 October 2026

Reviewed the working application in `placement_app/`, including models, forms, authentication, permissions, request handlers, migrations, resume storage, report generation, templates, JavaScript, startup, and existing tests. Original HTML mockups and the supplied documentation remain reference material.

## Confirmed defects and fixes

| Problem | Root cause and fix | Verification |
| --- | --- | --- |
| Malformed meeting URLs could crash interview scheduling. | Raw `urlsplit` raised on malformed IPv6 and did not reject bad ports or embedded credentials. The form now validates HTTP(S) URLs, catches parsing failures, and returns a field error. | Original parser crash reproduced; form regressions and real browser/API checks pass. |
| Application filters could produce HTTP 500 errors. | `str.isdigit()` accepted values such as `²`, while very large integers overflowed SQLite. The query boundary now accepts only positive ASCII IDs within SQLite's 64-bit range; malformed filters return an empty scoped result. URL record converters use the same database bounds. | Original query failures reproduced; malformed-filter HTTP checks and route tests pass. |
| Switching registration roles could leave errors in invisible fields. | Hidden student/company fields still participated in validation. Both the server form and browser now disable fields belonging to the other role, and account creation validates/inserts in one write transaction. | Baseline hidden-field failures reproduced; both-role registration tests and browser role switching pass. |
| Login uniqueness did not match email signup storage. | Database uniqueness was case-sensitive while sign-in used `iexact`. A database constraint now enforces case-insensitive email uniqueness. The inherited username field was also too short for valid email addresses and now supports the full email length. | Duplicate-case insertion and long-email model regressions pass. Existing database migrated without altering account credentials. |
| Unknown roles inherited broad application access. | `application_scope` returned all records for any role other than student/company. It now explicitly permits officers and denies other roles. Middleware also denies invalid workspace roles while allowing logout. | Source issue reproduced in scope tests; invalid-role access/logout regressions pass. |
| Existing applicants lost job details after a role closed or returned to review. | The detail handler required an open role for every student. It now preserves read access for the student's existing application while keeping non-applicants excluded. | Closed/pending role visibility and isolation regressions pass. |
| Search/job scope disappeared after application status actions. | Status chips constructed new query strings and decision handlers redirected to the unfiltered list. Chips/forms now preserve supported filters, with redirects constructed from the application route rather than caller-provided URLs. Status counts use the current search/job scope. | Template/redirect tests and browser checks pass. |
| Selected applications showed changed role/company/package values. | Some templates read live job values while confirmations/reports used saved selection facts. Application-owned display properties now select the saved terms consistently in application lists, dashboard activity, and interview history. | Changed-job/company regression passes; end-to-end selection and report workflow passes. |
| Completed/rejected interviews still offered an active joining link. | The template checked meeting format without the application state. Decided interviews retain their history but no longer display an actionable joining link. | Rejected-interview display regression passes. |
| Resume cleanup could fail after a committed update or leave a file after rollback. | File storage was treated as part of the DB transaction. Superseded files now enter a durable deletion queue in the profile transaction; deletion failures remain retryable. Written uploads are removed if the database/audit transaction rolls back. Referenced current resumes are never deleted by cleanup. Profile forms bind to a current locked account and save only submitted profile fields. | Baseline issue established from transaction/storage code. Injected file-lock and audit-failure regressions now pass, including retry and rollback cleanup. |
| Simultaneous writes could race uniqueness, approval, or interview checks. | SQLite deferred write transactions and pre-transaction model instances allowed stale checks. Local write workflows now use IMMEDIATE transactions, refresh the relevant accounts/jobs/applications in those transactions, and re-read the interview record before saving. | Two simultaneous apply requests produced one application; simultaneous conflicting interview requests saved one slot and returned a form conflict for the other. These were real HTTP requests against an isolated SQLite server. |
| Empty form submissions hid validation errors. | `request.POST or None` turned an empty POST into an unbound form. Forms now bind according to the request method. | Empty-profile POST regression passes. |
| Authenticated records had no explicit browser/proxy cache policy. | Workspace pages and exports now carry `private, no-store, no-cache, must-revalidate`. | Page/export header regressions and browser/API checks pass. |
| Collapsed mobile navigation remained in the keyboard focus order. | CSS moved the sidebar offscreen without disabling focus. Mobile navigation now uses `inert`, focuses the open menu, cycles keyboard focus, closes on Escape/outside interaction, and restores toggle focus. Desktop resizing restores normal navigation. | Real mobile browser focus, Escape, and resize checks pass. |
| Officer profiles and superuser creation used the wrong role assumptions. | Officers inherited the company profile form, and Django's superuser manager inherited the student/pending defaults. A personal officer form and explicit approved-officer superuser defaults resolve both. | Officer profile and superuser regressions pass. |
| Disabled recruiters and already-applied openings had inconsistent eligibility displays. | Availability now requires an active company; student dashboard recommendations exclude previously applied roles. | Inactive-company and dashboard-count regressions pass. |

## Verification limits

This review verifies the local Django/SQLite application. Browser smoke coverage is representative, not exhaustive accessibility certification. Simultaneous-write checks cover the tested request pairs, not sustained load, crashes, all request interleavings, or another database engine. There is no external email/SMS delivery, real employer integration, upload malware scanning, forgotten-password email service, production hosting, or signed employer offer flow. PDF download signatures and workflow access were tested; multilingual PDF typography was not exhaustively verified. Dependency installation consistency was checked; a separate third-party vulnerability audit was not performed.

The original ZIP is unchanged. The enhanced source archive was refreshed with the fixes, migrations, tests, and documentation; live databases, uploaded resumes, the signing key, and the virtual environment are excluded.
